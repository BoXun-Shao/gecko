# 需求書：建立 SDLC 流程規範

- **訪談日期**：2026-08-21
- **範圍/主題**：為肥尾日誌專案建立可依循的軟體開發生命週期（SDLC）規範，讓每次開發 session 都能遵循一致流程。

## 背景

專案原本是單一 HTML 檔、無建置流程的個人小工具，沒有任何開發流程規範。使用者希望建立自己的 SDLC 流程，並確保之後的開發都依此流程進行。

## 需求細項與決策

| 主題 | 決策 | 理由/備註 |
|---|---|---|
| 流程文件位置 | [CLAUDE.md](../../CLAUDE.md) | Claude Code 每次工作自動讀取的慣例文件，最省心 |
| 需求/待辦管理 | 獨立 [TODO.md](../../TODO.md)，分類 Bug/Feature/Chore | 取代 README 原本的 Roadmap 勾選清單 |
| 分支策略 | Trunk-based，直接在 `main` 開發 | 單人小型專案，不需要 feature branch 的額外管理成本 |
| 完成前品質關卡 | (1) 瀏覽器手動測試 (2) `/code-review` (3) README/TODO 同步更新 (4) 資料相容性檢查 | 專案無自動化測試框架，手動測試不可省略 |
| Commit 規範 | Conventional Commits（`feat:`/`fix:`/`docs:`/`chore:`/`refactor:`） | 與工具鏈銜接良好，未來可用於自動生成 CHANGELOG |
| 版本號 | 在 README 標註簡單版本號（如 `v0.1`），不做完整 semver | 小專案不需要正式版本管理 |
| 資料結構變更政策 | schema 變更**必須實作自動遷移邏輯**，不可要求使用者手動處理或遺失資料 | 守宮飼育史是無法重建的真實資料，資料遺失是不可接受的風險 |
| 流程強制方式 | 文件化 + hook 提醒 | 在 `.claude/settings.json` 設定 `PreToolUse` hook，`git commit` 前印出品質關卡提醒（非阻擋性） |

## 產出

- [CLAUDE.md](../../CLAUDE.md)
- [TODO.md](../../TODO.md)（含原 README Roadmap 項目遷移）
- [README.md](../../README.md)（新增版本號、Roadmap 改指向 TODO.md）
- `.claude/settings.json`（commit 前品質關卡提醒 hook）
