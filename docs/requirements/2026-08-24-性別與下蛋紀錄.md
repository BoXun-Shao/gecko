# 需求書：性別欄位擴充與下蛋紀錄

- **訪談日期**：2026-08-24
- **範圍/主題**：在新資料庫 schema 設計階段（[2026-08-23-資料庫化與商用架構規劃.md](2026-08-23-資料庫化與商用架構規劃.md) Phase 1）補上性別欄位的「未知」選項，並新增下蛋紀錄欄位。

## 背景

在討論資料庫化架構該從哪裡開始時，使用者指出：新 schema 設計階段就要把「性別」與「下蛋」相關欄位一併考慮進去，即使目前沒有繁殖計畫，避免日後想追蹤時要大改 schema。使用者飼養的品種主要是豹紋守宮與肥尾守宮，這兩種在幼體階段都可能難以肉眼判斷性別。

## 需求細項與決策

### 1. 性別欄位擴充

| 項目 | 決策 |
|---|---|
| 現況 | README 已記載現有「性別」欄位（公/母），新 schema 會直接承接 |
| 異動 | 由二選一（公/母）改為**三選一：公／母／未知**，新增「未知」選項 |
| 理由 | 豹紋守宮、肥尾守宮幼體階段常難以確認性別，需要能先標記「未知」，之後再更新 |

### 2. 新增：下蛋紀錄

| 欄位 | 說明 |
|---|---|
| 日期 | 必填 |
| 蛋數 | 數字 |
| 備註 | 自由文字（選填） |
| 綁定對象 | 綁定特定守宮（`geckoId`） |

**明確排除（本次不做）：**
- 受精狀態標記（受精/未受精/未知）
- 孵化追蹤（孵化日期、孵化結果、溫濕度控制等）
- 配對/血系/基因相關的繁殖管理功能

**理由**：目前沒有繁殖計畫，這次只是先把最基本的「事件發生過」記下來（日期、蛋數、備註），避免日後真的要繁殖時資料庫要大改。若之後有實際繁殖需求，應另開需求訪談，屆時再决定是否需要受精狀態、孵化追蹤等更完整的繁殖管理功能。

## 對現有規劃的影響

- 此需求屬於 [2026-08-23-資料庫化與商用架構規劃.md](2026-08-23-資料庫化與商用架構規劃.md) Phase 1（後端專案骨架：資料表設計）範圍內的欄位補充，不改變該需求書的整體架構決策（FastAPI + PostgreSQL + React、自建認證方向、seed 預設 user 等）。
- `gecko` 資料表的性別欄位定義（enum：`male`/`female`/`unknown`）與新增的 `egg_log`（或同等命名）資料表須在 Phase 1 schema 設計時一併納入。
