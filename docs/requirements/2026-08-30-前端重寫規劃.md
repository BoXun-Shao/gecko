# 需求書：前端重寫規劃（React + Mantine + Recharts）

- **訪談日期**：2026-08-30
- **範圍/主題**：淘汰 `index.html` 的 vanilla JS / localStorage 前端，改為呼叫既有 FastAPI 後端的 React SPA；並為後端已支援、但舊前端從未實作的三種紀錄類型（蛻皮、環境溫濕度、下蛋）設計全新 UI。

## 背景

依 [2026-08-23-資料庫化與商用架構規劃.md](2026-08-23-資料庫化與商用架構規劃.md) 的建議分期，後端骨架、全部 API endpoints（geckos + 四種紀錄類型 CRUD，含照片上傳與軟刪除 cascade，見 [2026-08-30-軟刪除cascade決策與API開發啟動.md](2026-08-30-軟刪除cascade決策與API開發啟動.md)）與一次性 Excel 遷移工具都已完成。現在啟動第 3 期：前端重寫。

舊版 `index.html` 是單頁式（roster chips 切換守宮 + 全部資訊垂直排列），只涵蓋進食/排便/體重紀錄。新架構下後端已多支援蛻皮、環境溫濕度、下蛋三種紀錄類型，若比照舊版全部塞在同一頁會過長，因此本次訪談同時決定新的導覽架構。

## 決策：技術選型

| 項目 | 決策 | 理由 |
|---|---|---|
| 框架 | Vite + React + TypeScript | React 生態標準搭配；TypeScript 搭配自動產生型別可讓後端 schema 異動時前端型別自動同步，5 組資源、不少欄位與 enum，手動同步容易漏改 |
| UI 元件庫 | Mantine | 有自己的主題系統，不需要 Tailwind；預計客製深色配色以延續舊版視覺語言，不採用預設配色 |
| 圖表 | Recharts | 涵蓋體重折線、進食長條（含粒度切換）、食物比例，以及新增的溫濕度趨勢、下蛋數圖表；開發與維護新圖表較手刻 SVG 快 |
| 60 天斑帶圖 | 不用 Recharts，改用 CSS Grid/Flex 手刻元件 | 舊版 signature 視覺（60 日進食狀態格 + 排便疊加點），非標準圖表型態，邏輯從 `drawBand()` 移植保留視覺語意 |
| API 型別 | openapi-typescript 從後端 `/openapi.json` 產生型別 + 手寫輕量 fetch wrapper | 型別隨後端 schema 自動同步；不引入 orval 等較重的產生工具，維持 wrapper 可控 |
| 資料層 | TanStack React Query | 5 組資源（geckos/daily-logs/shedding-logs/environment-logs/egg-logs）都需要 CRUD + loading/error/快取，用 React Query 統一處理，避免手寫重複狀態邏輯 |
| 導覽結構 | 頂部維持守宮 roster chips 切換，選定守宮後用 Tabs 呈現「總覽／進食／蛻皮／環境／下蛋」 | 舊版單頁式無法擴展到 3 種新紀錄類型 |
| 路由 | react-router，URL 可分享（例如 `/geckos/:geckoId/:tab`） | 讓某隻守宮的某個分頁籤可直接用網址分享/刷新保留，比純記憶體狀態多一點可用性 |
| 身份驗證 | 無登入 UI，沿用後端固定 seed user | 延續 [2026-08-23-資料庫化與商用架構規劃.md](2026-08-23-資料庫化與商用架構規劃.md) 決策，本次不實作登入 |

## 決策：新紀錄類型 UI

欄位定義以 `backend/app/schemas.py` 為準，不新增欄位：

- **蛻皮 (shedding) 紀錄**：日期、備註、多張照片（可上傳、瀏覽、個別刪除單張照片）。
- **環境溫濕度 (environment) 紀錄**：紀錄時間（`recorded_at`）、溫度、濕度、來源（手動/感測器）。每隻守宮可各自設定安全溫濕度範圍（`safe_temp_min/max`、`safe_humidity_min/max`），環境紀錄頁面需依該守宮自己的範圍判斷並標示超出範圍的讀數。
- **下蛋 (egg) 紀錄**：日期、蛋數、備註，不追蹤受精/孵化（沿用 [2026-08-24-性別與下蛋紀錄.md](2026-08-24-性別與下蛋紀錄.md) 決策）。

### 邊界情況：守宮未設定安全溫濕度範圍

若某隻守宮完全沒設定 `safe_temp/humidity min/max`，環境紀錄頁面**顯示提示，引導使用者去守宮設定頁補充**，而非靜默略過警告判斷。
