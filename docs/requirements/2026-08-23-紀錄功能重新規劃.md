# 需求書：紀錄功能重新規劃

- **訪談日期**：2026-08-23
- **範圍/主題**：全面重新檢視「紀錄」功能 —— 既有的進食／排便／體重紀錄，加上新增的蛻皮、環境溫濕度紀錄。

## 背景

專案目前的每日紀錄涵蓋進食（數量、餌料、尺寸、拒食/沒餵）、排便（有/無）、體重（選填數字）。使用者要求針對「紀錄」整體重新規劃，不預設現有欄位一定合理，並評估是否要新增其他紀錄類型。

## 範圍確認

**這次要做的：**
- 進食狀態重新設計
- 新增蛻皮紀錄
- 新增環境溫濕度紀錄

**明確排除（本次不做，之後如需要另開需求訪談）：**
- 除蟲/驅蟲用藥紀錄
- 健康/獸醫回診紀錄
- 行為/活動力觀察
- 換底材/清潔紀錄
- 泡澡紀錄
- 一天多餐（早晚分開記錄）
- 餌料庫存/來源追蹤

**維持現狀：**
- 排便紀錄維持「有/無」，不加質地/顏色欄位
- 體重紀錄維持現狀（選填數字）

## 需求細項與決策

### 1. 進食狀態重新設計

| 項目 | 決策 |
|---|---|
| 狀態列舉 | 四種：`fed`（已餵食）／`partial`（部分進食）／`refused`（拒食）／`skipped`（非餵食日沒餵） |
| `partial` 的資料需求 | 不新增「提供量」欄位；`qty` 欄位維持只記錄實際吃掉量，`partial` 只是額外的狀態標記 |
| 舊資料遷移規則 | `qty > 0` → `fed`；`skipped === true` → `skipped`；其餘（`qty === 0` 且非 skipped）→ `refused`。舊資料沒有「部分進食」的判斷依據，遷移後不會產生 `partial` 記錄，這是預期且合理的行為 |
| 餌料、尺寸欄位 | 維持不變 |

### 2. 新增：蛻皮紀錄

| 欄位 | 說明 |
|---|---|
| 日期 | 必填 |
| 備註 | 自由文字（選填） |
| 照片 | 可上傳多張 |
| 綁定對象 | 綁定特定守宮（`geckoId`），非全局共用 |

**技術風險提醒**：蛻皮紀錄允許多張照片、以 base64 存進 `localStorage`，會比現有單張大頭照顯著增加資料量（base64 編碼通常比原圖大 ~33%）。實作時若發現實際使用情境下容量逼近瀏覽器 `localStorage` 上限（一般 5–10MB），依 [CLAUDE.md](../../CLAUDE.md) 的規則須立即停下並與使用者重新確認（例如是否要壓縮圖片、限制單次上傳張數、或改變儲存策略），不可自行默默降規格。

### 3. 新增：環境溫濕度紀錄

| 項目 | 決策 |
|---|---|
| 欄位 | 單一溫度數值 + 單一濕度數值（每次量一組） |
| 頻率 | 每日固定量一次（無強制提醒機制，使用者自行決定何時記錄） |
| 綁定對象 | 每隻守宮各自登記（`geckoId`），因為每隻的飼育環境可能不同 |
| 資料來源 | 目前為人工輸入。未來想接 IoT 感測器自動記錄 —— **這次不實作**，但資料結構設計時應保留擴充空間（例如標記資料來源為 manual，未來可加 sensor 來源而不需要再次改 schema） |
| 安全範圍警示 | 需要。每隻守宮可以分別設定自己的安全範圍（溫度 min/max、濕度 min/max），超出範圍時介面顯示警示 |

## 資料相容性與遷移（依 CLAUDE.md 政策）

- `localStorage`（key: `fattail-gecko-log-v1`）schema 異動：
  - 進食紀錄新增/取代欄位：`qty` + `skipped` 布林值 → 新增 `status` 欄位（`fed`/`partial`/`refused`/`skipped`），須實作上表定義的自動遷移邏輯，讀取舊資料時自動轉換，不要求使用者手動處理。
  - 新增蛻皮紀錄與溫濕度紀錄的資料結構（新的紀錄類型，非既有欄位變更，不涉及舊資料遺失風險，但需確保 Excel 匯出/匯入格式同步支援）。
- Excel 匯出/匯入格式需同步更新，涵蓋新的 `status` 欄位與蛻皮、溫濕度兩種新紀錄類型，且舊版匯出檔案要能被新版正確匯入還原。
